# Contributing

1. Check Issues first. Explain the user problem, expected behaviour and a concrete example.
2. Include platform, browser, app version, language, theme and reproducible steps. Remove private names, tokens, emails and goals from screenshots.
3. Fork this repository, make a focused change, run `npm ci` and `npm run check`, and open a pull request.
4. Preserve keyboard support, meaningful labels, Russian/English, narrow layouts and live system-theme behaviour.
5. Use calendar date keys. Selecting a date must not toggle its mark. Notes and completion are separate concepts.

Good starting areas: date boundary tests, accessible calendars, empty states, translations, documentation and reusable components. Production access is not required.

Do not add trackers, new dependencies or account features without explaining the purpose. The local demo must work without a production account. Propose private feature changes as issues; their source is outside this repository.

Contributions are licensed under MIT. Disagree with ideas respectfully, without insulting people.
